# Divergences register: FINAL

The menus part's part of the register (DIVERGENCES.md says what an entry is). Ids D-100 and up.

| ID | Where | The original | The C# | Why |
|---|---|---|---|---|
| D-100 | `Headquarters.PostCaseVacation` | At the end gives the memory of the vacation's background image back to DOS: `_dos_freemem` (FINAL 0100:ea0a) of the segment `vacation_background` names. | Nothing: the images are objects, dropped when they are no longer used. | Images are typed objects in the rewrite, not DOS memory (D-11); nothing could observe the freed block. As D-402. |
| D-101 | `LibrarySaves.SelectSaveFile` | Installs a handler for DOS's critical errors around the write (`install_critical_error_handler`, FINAL 0100:0019, and its restore at 0100:003e), assembly that hooks INT 24h. | Nothing: there is no DOS; `SaveScreenState.SaveError` stays 0 unless a caller sets it. | The rewrite's files boundary has no critical-error interrupt. |
| D-103 | `FinalState` (`ICampaignTables.MessageBeforeFirst`) | The library's dossier and log routines read message -1, the 14 bytes in front of the case log (the end of city 15's record, a word of the message box, the count of persons), and may write it. | The typed values are read from city 15's police figure and sighting counter and the high byte of `Nperson`, as the campaign part's state does; a write to it is not carried back into city 15 (as D-200). | Typed records have no bytes in front of the table; no case reaches the write. |
| D-104 | `Headquarters.LeaveTheGame` (the debriefing's three exits: retiring, "End Game", "End Game" after saving; FINAL 0100:175e) | `exit()` is called without an argument: DOS gets the word the debriefing's prologue saved (`push si`, FINAL 0100:2764), the SI that title_startup had when it called the debriefing (0100:121b): 82h, which the C start-up leaves there: __setargv (FINAL 0100:c9ae) reads the command tail from PSP:81h, and the launcher gives an empty one. The exit code is 130. Seen in a run of the whole session mastermind-debrief answered with "End Game" (INT 21h AX=4C82h) and with the start registers' SI 0 and 1234h alike. | The exit code is 0. | As D-4: the launcher does not look at the exit code (its spawnl's result is dropped, COVERT 0000:0010); the rewrite's launcher reads 0 as the player's leaving and any other code as a part that failed on a file. |
| D-105 | `LibrarySaves.ListSaveSlot` (`SaveFileCodec.IsWhole`; FINAL 0100:9d3b, GAME 00f7:a519) | A slot is listed (and can be loaded) whenever its file opens. Loading reads whatever the file holds: a file shorter than its 1008-byte head is completed with what `load_game`'s stack held (GAME 00f7:aebb reads into a stack buffer and copies all of it into the hand-off block), counts of the cast and events beyond the tables' 32 and 64 records are read past the tables, and a file that ends early leaves the rest of the tables as the part had them (the title's tables in FINAL, the running case's in GAME): a campaign made of two. Such a file is what a full disk leaves (the original's save ignores a short write, item 14). | A file that does not hold its head and every table its counts say, or whose counts are beyond the tables, is listed as "(EMPTY)" and cannot be chosen; the menus part goes back to its main menu, the campaign goes on with its case. A longer file is read as by the original. | The original's result is undefined (the stack's bytes, memory behind the tables) or a mix of two campaigns that no play made; the rewrite would stop where it reads past its typed tables. A player can check it: cut a CV0.SVE short and look at the load screen (`DiskFailureTests`, SESSION-PROOF.md item 14). |
