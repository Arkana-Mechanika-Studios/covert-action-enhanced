# symbols/amiga-names.txt - original names from the Amiga version of Covert Action
#
# Source: amiga/files/disk1/covert (not committed), a stale debug build left on disk 1 of
# "Covert Action v447.101 (1992)": an AmigaOS hunk executable that declares 138 hunks but holds
# only hunks 0-7; it carries a SYMBOL table (232 names) and SAS/C 5.10 HUNK_DEBUG blocks for
# SPIES:game/covert.c (the global data of every module, with full struct types) and
# SPIES:code/main.c.  The game program amiga/files/disk1/game has the same data hunks 2/3
# byte for byte, so the names apply to it; its 68k code was matched against our C through
# its relocations.  Method and evidence in docs/amiga.md.
#
# Format:  <our label>  <original name>  ; <confidence>: <evidence>
#   our label: as in symbols/names.txt (labels not yet named there are marked); a struct field
#     is <table label>.<our field> (the campaign structs under the GAME table, the raid structs
#     under TAC, the port record under CODE 1250); D_game_760a+<off> = a field of the 0x28e-byte
#     scalar block (struct Plot in the original).
#   original name: in the rename section the OMF name exactly as in the Amiga symbol table
#     (leading underscore, case kept, e.g. _TheOrg1); in the fields section pl.field /
#     table[].field for a label inside a table and Struct.field for a struct member.
#   confidence: certain = the 68k code does what our C does with it (same constants, strings,
#     call order) or a reader copies it at the same shared offset; likely = same role and
#     layout without a statement-level match; guess = plausible only (not to be applied).
# In the evidence, F_<hunk>_<offset> is the 68k function at that hunk and hex offset of `game`,
# and 4-hex numbers like 6cb1 are our function stems.
# Name collisions to watch when applying them: docs/amiga.md, "Applying the names".
# One original variable can stand for several of our labels: the Amiga build is one program,
# the PC one has a private copy of each table and scalar in every module.
